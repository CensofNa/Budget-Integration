================================================================================
UAT DEPLOYMENT & DATA UPDATE GUIDE
================================================================================

This guide contains the step-by-step instructions for:
  TASK 1: Correcting and updating previously synced monthly actuals in the DB.
  TASK 2: Pushing the code modifications and database schema updates to UAT.

--------------------------------------------------------------------------------
TASK 1: UPDATE MONTHLY DATA FROM PREVIOUSLY SYNCED DATA
--------------------------------------------------------------------------------

Since the raw JSON response payload is already saved in the database under the
`integration_report_api_logs` table, you can re-run the pipeline stages directly
in the database without needing to make new API calls to Entrata. 

Follow these steps in your database editor (e.g., pgAdmin, DBeaver, or psql):

1. Query your target Sync Run ID (the past run you want to correct, e.g. July run):
   ```sql
   SELECT DISTINCT sync_run_id, created_at 
   FROM public.integration_report_api_logs
   WHERE report_name = 'income_statement'
     AND created_at < '2026-07-16 11:13:45'
   ORDER BY created_at DESC LIMIT 5;
   ```
   *Note: In the queries below, replace '59c973f7-01f3-4b6e-b597-42b8fa2e5115' 
   with your actual Sync Run ID.*

2. Delete previous 2026 actuals (clears duplicate/incorrect dates for all properties):
   ```sql
   DELETE FROM public.property_income_statement_actuals 
   WHERE fiscal_year = 2026;
   ```

3. Run the Staging Procedure:
   This parses the raw JSON logs and writes correct calendar month-end dates 
   (e.g., June 30, May 31) into the staging table, fixing the off-by-one drift.
   ```sql
   SELECT * FROM public.fn_stage_income_statement_actuals_from_logs(
     'b9a26559-9837-4215-95e9-f5ffd0a9fb5c'::uuid, -- company_id
     '38bc82c3-a017-49fc-a441-0c75994527dd'::uuid, -- organisation_id
     '00005001-2f79-ff92-71d4-43aa25eac701'::uuid, -- integration_source_id
     '59c973f7-01f3-4b6e-b597-42b8fa2e5115'::uuid, -- sync_run_id (Pass target UUID here)
     null::uuid                                    -- report_log_id (all logs)
   );
   ```

4. Run the Transform Procedure:
   ```sql
   SELECT * FROM public.fn_transform_income_statement_actuals(
     'b9a26559-9837-4215-95e9-f5ffd0a9fb5c'::uuid, -- company_id
     '38bc82c3-a017-49fc-a441-0c75994527dd'::uuid, -- organisation_id
     '00005001-2f79-ff92-71d4-43aa25eac701'::uuid, -- integration_source_id
     '59c973f7-01f3-4b6e-b597-42b8fa2e5115'::uuid  -- sync_run_id
   );
   ```

5. Run the Projection Procedure (ACTUALS Snapshot) for ALL properties in one go:
   ```sql
   SELECT * FROM public.fn_project_actuals_from_income_statement_actuals(
     'b9a26559-9837-4215-95e9-f5ffd0a9fb5c'::uuid, -- company_id
     '38bc82c3-a017-49fc-a441-0c75994527dd'::uuid, -- organisation_id
     '00005001-2f79-ff92-71d4-43aa25eac701'::uuid, -- integration_source_id
     '59c973f7-01f3-4b6e-b597-42b8fa2e5115'::uuid, -- sync_run_id
     null::uuid,                                   -- NULL (projects for ALL properties at once)
     2026                                          -- fiscal_year
   );
   ```

6. Sync the ACTUALS to the REFORECAST Snapshot with Cutoff (June 2026) for ALL properties in one go:
   ```sql
   SELECT * FROM public.fn_sync_actuals_to_reforecast(
     'b9a26559-9837-4215-95e9-f5ffd0a9fb5c'::uuid, -- company_id
     '38bc82c3-a017-49fc-a441-0c75994527dd'::uuid, -- organisation_id
     null::uuid,                                   -- NULL (syncs for ALL properties at once)
     2026,                                         -- fiscal_year
     null::uuid,                                   -- created_by
     '2026-06'::varchar                            -- reforecast_cutoff_month
   );
   ```

TASK 2: PUSH CODE & DATABASE UPDATES TO UAT
--------------------------------------------------------------------------------

To deploy Task 2, you must execute the database DDL updates in UAT, followed by
committing and pushing the modified TypeScript files.

### Step 2.1: Update Stored Procedures on UAT Database

Execute the following DDL scripts in your UAT database to align the schema modifications:

   ```sql
                            ELSE (gs.month_index - 1)

                    - interval '1 day'
                )::date AS post_month,

                (

                    )::date

                public.fn_parse_income_statement_numeric
                (
                    r.raw_record_payload ->> ('month_' || gs.month_index)
                ) AS actual_amount,

                public.fn_parse_income_statement_numeric
                (
                    r.raw_record_payload ->> 'total'
                ) AS total_amount,

                r.raw_record_payload
            FROM report_rows r
            CROSS JOIN LATERAL generate_series(1, 16) AS gs(month_index)
            WHERE r.created_at IS NOT NULL
              AND COALESCE(r.raw_record_payload ->> 'account_number', '') <> ''
              -- DYNAMIC COLUMN FILTERING:
              AND (
                  (r.request_payload -> 'filters' ->> 'show_periods_from' = '2' AND gs.month_index BETWEEN 1 AND (r.trailing_periods + 1))

                              ELSE (gs.month_index - 1)
                           END || ' month')::interval
                      ) + interval '1 month' - interval '1 day'
                  )::date) >= EXTRACT(YEAR FROM r.latest_post_month) - 1
              )
        )

        SELECT
            gen_random_uuid(),
            em.company_id,
            em.organisation_id,
            em.integration_source_id,
            em.sync_run_id,
            em.report_log_id,

            em.source_property_id,
   ```

2. Redefine `fn_transform_income_statement_actuals` to execute in high-performance bulk set-based mode:
   ```sql
   CREATE OR REPLACE FUNCTION public.fn_transform_income_statement_actuals(
       p_company_id uuid,
       p_organisation_id uuid,
       p_integration_source_id uuid,
       p_sync_run_id uuid
   )
    RETURNS TABLE(inserted_count integer, updated_count integer, warning_count integer, failed_count integer)
    LANGUAGE plpgsql
   AS $function$
   DECLARE
       v_inserted_count integer := 0;
       v_updated_count integer := 0;
       v_warning_count integer := 0;
       v_failed_count integer := 0;
       v_now timestamp(3) := CURRENT_TIMESTAMP;
   BEGIN
       -- 1. Create a temp table of resolved GL accounts and properties to transform using flat indexed joins
       CREATE TEMP TABLE tmp_resolved_rows ON COMMIT DROP AS
       SELECT
           sia.id AS staging_row_id,
           sia.company_id,
           sia.organisation_id,
           sia.integration_source_id,
           sia.sync_run_id,
           sia.report_log_id,
           sia.source_property_id,
           sia.property_id AS resolved_property_id,
           sia.property_code AS resolved_property_code,
           sia.gl_tree_id,
           sia.gl_book_id,
           sia.accounting_method,
           sia.account_number,
           sia.account_name AS sia_account_name,
           sia.gl_account_type_id,
           sia.account_path,
           sia.post_month,
           sia.fiscal_year,
           sia.actual_amount,
           sia.total_amount,
           sia.raw_record_payload,
           ga.id AS resolved_gl_account_id,
           ga.account_name AS resolved_gl_account_name
       FROM public.staging_income_statement_actuals sia
       LEFT JOIN public.gl_trees gt 
         ON gt.company_id = sia.company_id
        AND gt.organisation_id = sia.organisation_id
        AND gt.source_gl_tree_id = sia.gl_tree_id
       LEFT JOIN public.gl_accounts ga 
         ON ga.company_id = sia.company_id
        AND ga.organisation_id = sia.organisation_id
        AND ga.gl_tree_id = gt.id
        AND ga.account_number = sia.account_number
       WHERE sia.company_id = p_company_id
         AND sia.organisation_id = p_organisation_id
         AND sia.integration_source_id = p_integration_source_id
         AND sia.sync_run_id = p_sync_run_id
         AND sia.transform_status IN ('PENDING', 'FAILED', 'TRANSFORMED_WITH_WARNING');

       -- 2. Mark failed properties (in case property_id is null in staging)
       UPDATE public.staging_income_statement_actuals sia
       SET
           transform_status = 'FAILED',
           transform_errors = jsonb_build_object(
               'reason', 'PROPERTY_NOT_FOUND',
               'message', 'Unable to resolve property. property_id is null in staging table.',
               'source_property_id', t.source_property_id,
               'property_code', t.resolved_property_code,
               'property_id', t.resolved_property_id
           ),
           transformed_at = v_now,
           updated_at = v_now
       FROM tmp_resolved_rows t
       WHERE sia.id = t.staging_row_id
         AND t.resolved_property_id IS NULL;

       GET DIAGNOSTICS v_failed_count = ROW_COUNT;

       -- Delete failed rows from temp table so they aren't upserted
       DELETE FROM tmp_resolved_rows WHERE resolved_property_id IS NULL;

       -- 3. Create notifications in bulk for missing COA accounts
       INSERT INTO public.integration_data_notifications
       (
           id,
           company_id,
           organisation_id,
           integration_source_id,
           sync_run_id,
           report_log_id,
           notification_type,
           severity,
           entity_type,
           source_property_id,
           property_id,
           property_code,
           source_account_number,
           source_account_name,
           message,
           details,
           status,
           created_at
       )
       SELECT DISTINCT ON (t.resolved_property_id, t.account_number)
           gen_random_uuid(),
           p_company_id,
           p_organisation_id,
           p_integration_source_id,
           p_sync_run_id,
           t.report_log_id,
           'MISSING_COA_ACCOUNT',
           'WARNING',
           'IncomeStatementActuals',
           t.source_property_id,
           t.resolved_property_id,
           t.resolved_property_code,
           t.account_number,
           t.sia_account_name,
           'Account from Entrata income_statement report was not found in gl_accounts. Actuals were still transformed using source account number/name.',
           jsonb_build_object(
               'source_property_id', t.source_property_id,
               'property_id', t.resolved_property_id,
               'property_code', t.resolved_property_code,
               'gl_tree_id', t.gl_tree_id,
               'gl_book_id', t.gl_book_id,
               'account_number', t.account_number,
               'account_name', t.sia_account_name,
               'post_month', t.post_month,
               'fiscal_year', t.fiscal_year
           ),
           'OPEN',
           v_now
       FROM tmp_resolved_rows t
       WHERE t.resolved_gl_account_id IS NULL
         AND NOT EXISTS (
             SELECT 1
             FROM public.integration_data_notifications n
             WHERE n.company_id = p_company_id
               AND n.organisation_id = p_organisation_id
               AND n.integration_source_id = p_integration_source_id
               AND n.notification_type = 'MISSING_COA_ACCOUNT'
               AND n.entity_type = 'IncomeStatementActuals'
               AND n.source_property_id::text = t.source_property_id::text
               AND n.source_account_number::text = t.account_number::text
               AND n.status = 'OPEN'
         );

       -- 4. Bulk upsert canonical actuals (using DISTINCT ON to prevent duplicate conflict values)
       SELECT COUNT(*)
       INTO v_updated_count
       FROM (
           SELECT DISTINCT ON (
               t.company_id,
               t.organisation_id,
               t.integration_source_id,
               t.resolved_property_id,
               t.fiscal_year,
               DATE_TRUNC('month', t.post_month)::date,
               t.gl_tree_id,
               t.gl_book_id,
               t.account_number
           ) t.*
           FROM tmp_resolved_rows t
           ORDER BY
               t.company_id,
               t.organisation_id,
               t.integration_source_id,
               t.resolved_property_id,
               t.fiscal_year,
               DATE_TRUNC('month', t.post_month)::date,
               t.gl_tree_id,
               t.gl_book_id,
               t.account_number,
               t.staging_row_id DESC
       ) t
       JOIN public.property_income_statement_actuals pisa
         ON pisa.company_id = p_company_id
        AND pisa.organisation_id = p_organisation_id
        AND pisa.integration_source_id = p_integration_source_id
        AND pisa.property_id = t.resolved_property_id
        AND pisa.fiscal_year = t.fiscal_year
        AND pisa.post_month = DATE_TRUNC('month', t.post_month)::date
        AND COALESCE(pisa.gl_tree_id, '') = COALESCE(t.gl_tree_id, '')
        AND COALESCE(pisa.gl_book_id, '') = COALESCE(t.gl_book_id, '')
        AND pisa.account_number = t.account_number;

       INSERT INTO public.property_income_statement_actuals
       (
           id,
           company_id,
           organisation_id,
           integration_source_id,
           sync_run_id,
           report_log_id,
           property_id,
           property_code,
           source_property_id,
           fiscal_year,
           post_month,
           gl_tree_id,
           gl_book_id,
           accounting_method,
           coa_id,
           account_number,
           account_name,
           gl_account_type_id,
           account_path,
           actual_amount,
           total_amount,
           source_system,
           raw_record_payload,
           imported_at,
           created_at,
           updated_at
       )
       SELECT DISTINCT ON (
           t.company_id,
           t.organisation_id,
           t.integration_source_id,
           t.resolved_property_id,
           t.fiscal_year,
           DATE_TRUNC('month', t.post_month)::date,
           t.gl_tree_id,
           t.gl_book_id,
           t.account_number
       )
           gen_random_uuid(),
           t.company_id,
           t.organisation_id,
           t.integration_source_id,
           t.sync_run_id,
           t.report_log_id,
           t.resolved_property_id,
           t.resolved_property_code,
           t.source_property_id,

       v_inserted_count := v_inserted_count - v_updated_count;

       -- Count warning rows
       SELECT COUNT(*)
       INTO v_warning_count
       FROM tmp_resolved_rows t
       WHERE t.resolved_gl_account_id IS NULL;

       -- 5. Bulk update staging table statuses
       UPDATE public.staging_income_statement_actuals sia

       updated_count := v_updated_count;
       warning_count := v_warning_count;
   ```

   ```sql
                   may_amount,
                   jun_amount,
                   jul_amount,
                   aug_amount,
                   sep_amount,
                   oct_amount,
                   nov_amount,
                   dec_amount,
                   full_year_amount,
                   notes,
                   created_at,
                   updated_at
               )
               SELECT
                   gen_random_uuid() AS calc_line_id,
                   v_reforecast_snapshot_id AS snapshot_id,
                   abcl.company_id,
                   abcl.organisation_id,
                   abcl.property_id,
                   abcl.fiscal_year,
                   'REFORECAST' AS snapshot_type,
                   abcl.coa_id,
                   abcl.account_code,
                   abcl.account_name,
                   abcl.account_group,
                   abcl.line_code,
                   abcl.line_name,
                   abcl.line_type,
                   abcl.parent_line_code,
                   abcl.sort_order,
                   abcl.is_editable,
                   abcl.is_calculated,
                   abcl.is_reference,
                   abcl.formula_json,
                   CASE WHEN v_cutoff_month_index >= 1 THEN abcl.jan_amount ELSE 0 END,
                   CASE WHEN v_cutoff_month_index >= 2 THEN abcl.feb_amount ELSE 0 END,
                   CASE WHEN v_cutoff_month_index >= 3 THEN abcl.mar_amount ELSE 0 END,
                   CASE WHEN v_cutoff_month_index >= 4 THEN abcl.apr_amount ELSE 0 END,
                   CASE WHEN v_cutoff_month_index >= 5 THEN abcl.may_amount ELSE 0 END,
                   CASE WHEN v_cutoff_month_index >= 6 THEN abcl.jun_amount ELSE 0 END,
                   CASE WHEN v_cutoff_month_index >= 7 THEN abcl.jul_amount ELSE 0 END,
                   CASE WHEN v_cutoff_month_index >= 8 THEN abcl.aug_amount ELSE 0 END,
                   CASE WHEN v_cutoff_month_index >= 9 THEN abcl.sep_amount ELSE 0 END,
                   CASE WHEN v_cutoff_month_index >= 10 THEN abcl.oct_amount ELSE 0 END,
                   CASE WHEN v_cutoff_month_index >= 11 THEN abcl.nov_amount ELSE 0 END,
                   CASE WHEN v_cutoff_month_index >= 12 THEN abcl.dec_amount ELSE 0 END,
                   (CASE WHEN v_cutoff_month_index >= 1 THEN abcl.jan_amount ELSE 0 END) +
                   (CASE WHEN v_cutoff_month_index >= 2 THEN abcl.feb_amount ELSE 0 END) +
                   (CASE WHEN v_cutoff_month_index >= 3 THEN abcl.mar_amount ELSE 0 END) +
                   (CASE WHEN v_cutoff_month_index >= 4 THEN abcl.apr_amount ELSE 0 END) +
                   (CASE WHEN v_cutoff_month_index >= 5 THEN abcl.may_amount ELSE 0 END) +
                   (CASE WHEN v_cutoff_month_index >= 6 THEN abcl.jun_amount ELSE 0 END) +
                   (CASE WHEN v_cutoff_month_index >= 7 THEN abcl.jul_amount ELSE 0 END) +
                   (CASE WHEN v_cutoff_month_index >= 8 THEN abcl.aug_amount ELSE 0 END) +
                   (CASE WHEN v_cutoff_month_index >= 9 THEN abcl.sep_amount ELSE 0 END) +
                   (CASE WHEN v_cutoff_month_index >= 10 THEN abcl.oct_amount ELSE 0 END) +
                   (CASE WHEN v_cutoff_month_index >= 11 THEN abcl.nov_amount ELSE 0 END) +
                   (CASE WHEN v_cutoff_month_index >= 12 THEN abcl.dec_amount ELSE 0 END),
                   abcl.notes,
                   CURRENT_TIMESTAMP AS created_at,
                   CURRENT_TIMESTAMP AS updated_at
               FROM public.budget_calc_lines abcl
               WHERE abcl.snapshot_id = v_actuals_snapshot_id
                 AND abcl.snapshot_type = 'ACTUALS'
                 AND NOT EXISTS (
                     SELECT 1
                     FROM public.budget_calc_lines rbcl
                     WHERE rbcl.snapshot_id = v_reforecast_snapshot_id
                       AND rbcl.snapshot_type = 'REFORECAST'
                       AND rbcl.line_code = abcl.line_code
                 );

               GET DIAGNOSTICS v_inserted_calc_line_count = ROW_COUNT;
               
               v_total_inserted := v_total_inserted + v_inserted_calc_line_count;
               v_total_updated := v_total_updated + v_updated_calc_line_count;
               v_props_synced := v_props_synced + 1;
           END IF;
       END LOOP;

       success := true;
       message := 'REFORECAST snapshots synced successfully for ' || v_props_synced || ' properties with cutoff ' || p_reforecast_cutoff_month;
       actuals_snapshot_id := NULL;
       reforecast_snapshot_id := NULL;
       inserted_calc_line_count := v_total_inserted;
       updated_calc_line_count := v_total_updated;
       
       RETURN NEXT;
       RETURN;

   EXCEPTION
       WHEN OTHERS THEN
           success := false;
           message := SQLERRM;
           actuals_snapshot_id := NULL;
           reforecast_snapshot_id := NULL;
           inserted_calc_line_count := 0;
           updated_calc_line_count := 0;
           RETURN NEXT;
           RETURN;
   END;
   $function$;
   ```
